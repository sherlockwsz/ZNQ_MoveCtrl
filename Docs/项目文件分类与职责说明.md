# ZNQ_MoveCtrl 项目文件分类与职责说明

整理日期：2026-09-05  
适用版本：TwinCAT 3.1.4026，当前实现14轴统一索引、13轴NC接入与HMI心跳保护

## 1. 整理原则

1. 按“类型、全局接口、轴控制、系统通信、顶层程序”划分目录。
2. 轴相关 ADS 路径统一调整为数组，通过 `GVL_AxisIndex` 的业务编号访问。
3. 看门狗只判断通信状态，不直接访问某一根轴。
4. 轴命令清理、重新授权和最终控制许可由独立命令保护块负责。
5. `FB_AxisManager` 组合命令保护与单轴控制，`MAIN` 只负责顶层调用和公共状态发布。
6. `FB_AxisControl` 主体仅保留有固定顺序的 Method 调用；跨 Method 状态集中到 `ST_AxisControlInternal`。
7. 不为尚未实现的功能保留空 FB，后续真正开发时再按对应模块新增。

## 8. FB_AxisControl Method 调用链

`FB_AxisControl` 主体按照以下顺序调用，顺序具有业务含义：

| 顺序 | Method | 作用 |
|---:|---|---|
| 1 | `M_ReadAxisStatus` | 每周期唯一一次调用 `AxisRef.ReadStatus()`。 |
| 2 | `M_ClearCycleResults` | 清除只保持一个扫描周期的完成、终止、拒绝和警告结果。 |
| 3 | `M_UpdateCommandEdges` | 更新 Reset、MoveAbs、MoveRel 和点动边沿。 |
| 4 | `M_UpdateSoftLimitState` | 检查限位配置、坐标基准、点动方向和定位目标。 |
| 5 | `M_UpdateCommandArbitration` | 汇总运动状态、生成停止请求、选择唯一命令并锁存 Stop。 |
| 6 | `M_ExecutePowerReset` | 周期调用 `MC_Power/MC_Reset`。 |
| 7 | `M_ExecuteJog` | 参数及方向校验后周期调用 `MC_Jog`。 |
| 8 | `M_ExecutePositioning` | 管理绝对/相对运动 Execute 锁存并调用对应 MC 块。 |
| 9 | `M_ExecuteStop` | 最后调用 `MC_Stop`，保证停止具有最终优先级。 |
| 10 | `M_UpdateError` | 汇总并锁存本周期最新 MC/NC 错误。 |
| 11 | `M_UpdateBasicState` | 更新 Power、Ready、Homed、Busy、Active 等基础状态。 |
| 12 | `M_UpdateMotionState` | 输出唯一的 `E_AxisMotionState`。 |
| 13 | `M_UpdateAxisData` | 更新 NC 位置、速度、加速度、力矩等实时数据。 |
| 14 | `M_UpdateMotionDirection` | 根据运动状态和速度生成正/负/无方向。 |

`M_SelectCommand` 是 `M_UpdateCommandArbitration` 使用的内部纯仲裁方法，优先级为：

```text
Stop > Reset > Jog > MoveAbsolute / MoveRelative
```

## 9. 顶层调用链

```text
MAIN
├─ FB_HmiWatchdog
│  ├─ M_ResolveTimeout
│  └─ M_UpdateHeartbeat
└─ aAxisManagers[1..14]
   ├─ FB_AxisCommandGuard
   │  ├─ M_AreCommandsSafe
   │  └─ M_ClearCommands
   └─ FB_AxisControl
      └─ 14个有序Method + PLCopen MC功能块
```

关键扫描顺序：

1. 看门狗先输出本周期通信状态。
2. AxisManager 将通信状态交给 CommandGuard。
3. 每根已配置轴的 Guard 在控制许可失效时先清除对应外部命令。
4. AxisControl 在同一扫描周期收到 `bControlAllowed = FALSE`，运动中会请求受控停止。
5. `MC_Stop` 完成并释放后，`MC_Power` 才撤销使能。

## 10. 看门狗与重新授权行为

| 场景 | `bOnline` | `bTimeout` | `bControlAllowed` | 处理结果 |
|---|---:|---:|---:|---|
| 看门狗禁用 | TRUE | FALSE | TRUE | 保持原有单轴调试行为。 |
| 启用后尚未收到新心跳 | FALSE | FALSE | FALSE | 清命令，等待新心跳。 |
| 心跳正常 | TRUE | FALSE | TRUE | 允许 HMI 控制。 |
| 心跳超时 | FALSE | TRUE | FALSE | 清命令，运动中受控停止并最终掉使能。 |
| 心跳恢复但旧命令未清零 | TRUE | FALSE | FALSE | 继续清命令并保持重新授权锁存。 |
| 心跳恢复且命令安全 | TRUE | FALSE | TRUE | 解除锁存，但 `bEnable` 已清零，必须人工重新使能。 |

## 14. 多轴扩展规则

14轴已经按统一数组组织。新增或接入轴时，只更新固定业务编号对应的NC映射和 `AxisLimits[index].bConfigured`，不再复制不同名称的单轴控制逻辑。整机模式、安全联锁和自动流程应位于 AxisManager 上层，不直接修改 PLCopen 单轴控制核心。
